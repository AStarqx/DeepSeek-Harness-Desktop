# Agent Note：桌面版窗口内标题栏、品牌标识与应用图标

Status: implemented

[English](2026-09-11-desktop-in-window-title-bar.md) | 中文

## 问题

外壳设置了原生应用菜单，而 Electron 会把该菜单渲染成窗口标题栏下方的独立一行。因此 Windows 和 Linux 出现了两行窗口装饰：一行是带会话文档标题的标题栏，其下是一行只有 **应用** 一项的菜单栏。窗口也没有图标，任务栏、安装程序以及窗口本身都停留在 Electron 的默认图案上，而客户端绘制的却是 DeepSeek 标识。

## 决策

[`desktopOwnsWindowChrome`](../../../../apps/desktop/src/titlebar.ts) 决定外壳是否把应用菜单放进自己的标题栏。除 macOS 之外的平台都这样做；macOS 按该平台的惯例把菜单保留在系统菜单栏中。

Windows 与 Linux 的窗口设置 `titleBarStyle: 'hidden'`，并使用高度等于标题栏、颜色透明的 `titleBarOverlay`。系统仍然在页面之上绘制最小化、最大化和关闭控件，因此窗口既去掉了标题文字，又保留了原生控件行为，包括贴靠布局与高对比度渲染。

每个窗口的 preload 通过 `installDesktopTitleBar` 注入标题栏：以文档自身文字颜色内联绘制的 DeepSeek 标识、一个使用外壳语言包 `application` 文案的按钮、拖拽区域，以及为标题栏预留一行的页面偏移。按钮打开应用菜单，该菜单由主进程构建一次，并在按钮上报的锚点处弹出。渲染进程上报标题栏实际渲染的文字颜色，主进程将其应用为窗口控件符号色，使主题切换后控件仍然清晰可辨。

标题栏通过 CSSOM 采纳的样式表设置样式。外壳文档声明了 `style-src 'self'`，会拒绝 `<style>` 元素和 style 属性；而被采纳的样式表不受该策略约束。

应用图标由仓库自有的鲸鱼图形（`FISH_LOGO_PATH`）渲染得到：`apps/desktop/build/icon.png` 与 `icon.ico` 供 electron-builder 的 Windows、macOS、Linux 目标使用，`apps/desktop/renderer/app-icon.png` 用作运行中应用的窗口图标。

## 考虑过的替代方案

**用 `autoHideMenuBar` 隐藏原生菜单栏。** 只要用户按下 Alt，这一行就会回来，而菜单在标题栏中依然没有位置，两行窗口装饰只是退到一个按键之外。

**在无边框窗口中自绘窗口控件。** 自绘控件会失去系统的贴靠布局、高对比度渲染与平台无障碍能力，还需要为最小化、最大化和关闭再增加一套 IPC。

**上报不透明的覆盖层颜色，而不是透明色。** 页面本身已经绘制了该区域，只有符号颜色需要跟随主题；不透明颜色会为同一片像素引入第二个事实来源。

**在窗口栏中保留文档标题。** 客户端已经在自己的页头绘制会话标题，窗口栏只是重复了它。

## 影响

窗口只有一行装饰。会话标题不再出现在窗口栏中；客户端仍然设置 `document.title`，供读取它的平台界面使用。

每个外壳文档都按标题栏高度偏移，包括启动页、插件管理器与恢复文档，因此没有页面内容会被系统控件遮挡。

外壳在 `apps/desktop/src/brand.ts` 中自有一份鲸鱼路径，因为窗口装饰文档无法导入浏览器插件包。`packages/client/ui-primitives/src/FishLogo.tsx` 仍是视觉上的权威来源。

验证：运行中的开发版应用显示出一行标题栏，包含标识、本地化菜单与系统控件；点击菜单按钮弹出了原生菜单；切换主题后上报的控件颜色随之更新；窗口图标句柄返回鲸鱼图标。测试覆盖了渲染进程的注入、锚点与颜色校验、两个 preload 的传输接线，以及窗口装饰选项。
